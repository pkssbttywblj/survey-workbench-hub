# 运行目录与命名规范

skill 每次运行都在**当前工作目录**下建一个调研库 `survey_<主题slug>/`（可用 `--root` 指定路径）。
目录结构、命名、ID 全部由脚本落地，**不要手工移动或改名**——`organize.py` / `build_index.py` 会重算。

---

## 1. 目录树

```
survey_<主题slug>/
├── 00_索引/
│   ├── 索引表.xlsx           # 主索引，6 个 sheet，见 §4
│   ├── 索引表.csv            # 总表 CSV 备份（utf-8-sig，Excel 直接开）
│   ├── library.db            # SQLite，query.py 的数据源
│   ├── tree.txt              # 目录树快照
│   └── 检索记录.json          # 全部检索的原始返回（合并去重后）
├── 01_文献/                   # 只放论文类：期刊/会议/预印本/学位论文
│   ├── 中文_核心/
│   ├── 中文_非核心/
│   ├── 英文_SCI1区/
│   ├── 英文_SCI2区/
│   ├── 英文_SCI3区/

│   ├── 英文_非SCI/
│   └── 等级待核实/

│   ├── tables/               # <id>_t<n>.csv 抽出的表格

│   ├── 文献获取指引.md        # 28 个检索渠道 + 逐条下载步骤 + 机构授权询问（可选）
│   └── figures/

    └── logs/
```

**红线**：`01_文献/` 与 `02_开放资料/` 里只允许出现归类好的成品文件，
任何 json/csv/txt/md 过程文件一律留在 `.cache/` 或 `00_索引/`。

## 2. ID 体系

| 前缀 | 含义 | 编号 |
|---|---|---|
| `P` | paper，论文类（进 `01_文献/`） | P001 起 |
| `O` | open material，非论文公开资料（进 `02_开放资料/`） | O001 起 |

ID 一经分配终身不变，贯穿：Excel 首列、笔记文件名、`fulltext.jsonl`、SQLite 主键、报告引文映射。
文件重命名不会改 ID；文件移动不会改 ID。

## 3. 文件命名

```
<年份>_<第一作者>_<中文短标题>__<来源>_<类型>_<获取>_<等级>.<ext>
```

示例：

```
2023_Raman_旋转爆轰非理想性__OpenAlex_J_闭源_Q1.pdf
2021_王兵_爆震发动机研究进展__Crossref_J_闭源_核心.pdf
2024_SJTU推进中心_爆轰仿真年度报告__网页_R_公开_NA.pdf
2022_Zhang_化学动力学代理模型__Zenodo_C_公开_NA.pptx
```

字段规则：

| 字段 | 取值 |
|---|---|
| 年份 | 4 位；无年份写 `nd` |
| 第一作者 | 英文只取姓（`Raman`、`Zhang`）；中文取全名（`王兵`）；无作者写 `Anon` |
| 中文短标题 | ≤14 字，概括核心，去掉副标题和标点 |
| 来源 | 实际检索源：`OpenAlex` `Crossref` `arXiv` `EuropePMC` `DOAJ` `Zenodo` `Figshare` `Semantic` `Web` `Manual` `Zotero` |
| 类型 | `J` 期刊 / `C` 会议 / `P` 预印本 / `D` 学位论文 / `R` 报告·白皮书 / `S` 幻灯片 / `W` 网页 / `M` 专著·标准 / `Dset` 数据集 / `SW` 软件·代码 / `O` 其他 |
| 获取 | `公开` 顺利公开下载 / `OA` 开放获取但走了站点跳转 / `闭源` 仅拿到摘要 / `直链` 第三方镜像 |
| 等级 | `1区`~`4区`（中科院） / `Q1`~`Q4`（JCR，无中科院分区时） / `核心` / `非核心` / `非SCI` / `NA`（非论文类） / `待核实` |

字段分隔符固定 `__`（双下划线），字段内分隔符 `_`（单下划线）。
非法字符 `< > : " / \ | ? *` 一律删掉，空格转 `_`，全角标点转半角。
重名时追加 `_2`、`_3`。
文件名总长超过 120 字符时，优先压缩「中文短标题」到 10 字。

**目录归类与文件名等级必须一致**：`英文_SCI1区/` 里的文件，其等级字段必须是 `1区`。
不一致会被 `build_index.py` 标为 `状态=不一致`。

## 4. 索引表.xlsx 结构

### sheet1 `总索引`（主表，按 ID 排序）

| 列 | 字段 | 说明 |
|---|---|---|
| A | ID | P001 / O001 |
| B | 标题 | 原文标题 |
| C | 中文题名 | 译名（论文类必填） |
| D | 第一作者 | |
| E | 年份 | |
| F | 期刊/来源 | 期刊名或站点名 |
| G | 类型 | J/C/P/D/R/S/W/M/Dset/SW |
| H | 语言 | 中文/英文 |
| I | 获取状态 | 公开/OA/闭源/直链 |
| J | 影响因子 | 数字，未知留空 |
| K | 分区 | 1区..4区/Q1../核心/非SCI/NA/待核实 |
| L | 被引 | 数字 |
| M | DOI | |
| N | 链接 | 可点，指向可下载页或摘要页 |
| O | 本地文件 | **超链接**到文件相对路径 |
| P | 解析全文 | **超链接**到 `03_解析全文/md/…` |
| Q | 笔记 | **超链接**到 `04_精读笔记/…` |
| N | 链接 | **超链接**；无落地页时用 DOI 解析地址兜底，不留空 |
| R | 相关度 | ★1–5（AI 判） |
| S | 标签 | 分号分隔，如 `方法;数据驱动;RDE` |
| T | 一句话说明 | ≤60 字，这份资料能支撑报告的哪个判断 |
| U | 核心结论 | 可引用的量化结论，带数值 |
| V | 状态 | 已入库/待手动获取/待多模态提取/解析失败/需OCR/不一致 |
| W | 入库时间 | |

一次性设置：首行冻结、自动筛选、列宽自适应、`获取状态=闭源` 行浅黄底、
`状态=待手动获取` 行浅红底、`相关度≥4` 的 ID 列加粗。

### sheet2 `待手动获取`
列：`ID` `标题` `年份` `DOI` `链接` `出版方` `推荐通道` `一键检索` `失败原因` `操作说明` `预计耗时`

- `标题` 与 `链接` 两列都是**超链接**，点标题直接跳出版方页面
- `一键检索` 是渠道检索页的超链接（显示渠道名而非长 URL），按**标题**检索；
  取值来自 `channels.py recommend()`，中文条目给知网/万方，AIAA 给 AIAA ARC，Elsevier 给 ScienceDirect
- `链接` 的取值优先级：`https://doi.org/<DOI>` > 抓取时的落地页 > 按标题的 Bing 检索地址
  （最后一档只用于既无 DOI 又无原址的条目，`未获取资料清单.md` 里会标成「检索」而非「打开」）
- `失败原因` 照抄 `acquire.py` 给出的判定（出版社 403 / 只取到落地页 / 网络不可达）
- `推荐通道` 取值：`机构CARSI` / `Zotero+sci-pdf` / `图书馆文献传递` / `作者主页` / `ResearchGate` / `知网`
- `操作说明` 按通道给标准步骤（`CHANNEL_STEPS` 常量，Excel 与 md 清单共用一份），不许写「请自行获取」

同内容另出一份 `05_报告/未获取资料清单.md`：按通道分组、逐条一行（ID · 年份 · 标题 · DOI · 链接 · 一键检索 · 失败原因），
末尾附各通道操作步骤与「拿到之后怎么入库」的命令。这份是可直接转发的交付物。

`build_index.py` 每次运行还会用 `channels.py` 生成 `05_报告/文献获取指引.md`：
机构授权询问（只问一次，答「没有」就走 NSTL）、逐条 DOI 直链与最多 4 个渠道入口、
以及 28 个渠道的总表。无待获取项时这份文件会被改写成「无需补全文」，不留旧状态。

### sheet3 `解析状态`
列：`ID` `文件名` `页数` `字符数` `每页均字符` `文本层` `取文方式` `是否OCR` `表格数` `耗时秒`
`文本层` = `正常` / `稀疏`（<200 字/页）/ `无`。
`取文方式` = `文本层` / `OCR` / `多模态` / `多模态待提取` —— 决定这份文字可不可信、要不要回原图核对。

### sheet4 `表格清单`
列：`ID` `文献` `表号` `表名/首行` `行×列` `CSV路径` `备注`
论文里抽出的表格在这里登记，方便「按表格横向对比」。

### sheet5 `标签统计`
列：`标签` `数量` `代表ID（前3）`

### sheet6 `检索记录`
列：`时间` `关键词` `数据源` `命中` `去重后` `备注`

### sheet7 `说明`
| 项目 | 说明 |
|---|---|
| 表格提取 | 当前由 pdfplumber 抽取；高精度需求安装 OCR 后让 agent 跑 `table_ocr.py extract` |
| OCR 选型 | 优先本机 MiniOCR；可选 HunyuanOCR-1.5（1B）或 PaddleOCR-VL（约 0.9B） |
| 网页资料 | HTML 原件归入 `02_开放资料/网页存档` 并转 md 可检索 |

## 5. 状态机

```
检索 → 候选(未入库) → 获取成功 → 已入库
                              ├→ 文本层可用 → 已解析 → 有笔记 → 已精读
                              ├→ 无文本层 + 有OCR → 已解析（取文方式=OCR）
                              ├→ 无文本层 + 无OCR → 待多模态提取 → --ingest → 已解析（取文方式=多模态）
                              └→ 加密/损坏 → 解析失败（附原因）
                    ↘ 获取失败 → 待手动获取（附通道+步骤）
```

`query.py stats` 随时打印各状态计数，作为「资料库健康状况」指标。
`待多模态提取` 是**中间态不是终态**：agent 必须用视觉能力把页面图读出来回写，才算走完。
