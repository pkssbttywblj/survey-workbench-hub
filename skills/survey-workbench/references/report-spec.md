# 基金申请书「国内外研究现状」写作规范

本规范从一份已定稿的国家自然科学基金申请书（面上/青年类，正文 41735 字）中逐段量化提取，
是本 skill 生成调研报告的**唯一格式依据**。除非用户在交互中显式改动，一律按此执行。

---

## 1. 硬性量化基准

| 项 | 基准值 | 说明 |
|---|---|---|
| 「国内外研究现状」正文字数 | **3500 字 ± 15%**（样张 3519） | 不含参考文献 |
| 「发展动态分析及问题分析」字数 | **1750 字 ± 15%**（样张 1757） | 独立成一节，不并入研究现状 |
| 两部分比例 | 约 **2 : 1** | 现状铺陈是主体，动态分析是收口 |
| 参考文献条数 | **80–120 条**（样张 113） | 中英文混排，中文占比 20%–35% |
| 单个研究阶段/小节字数 | 700–1000 字（2 段） | 每段 300–670 字，普遍 400 字左右 |
| 单段上限 | 700 字 | 超过就该拆段 |
| 阶段/小节数量 | **3 个阶段**（默认，time）/ 4 个主题（topic，样张 4 个） | 阶段按年跨度等分；主题按"物理现象／理论／方法／交叉技术"切分 |
| 图表数 | 2 张逻辑图 + 1 张时间轴表 | 图1 调研总体逻辑图、图2 核心问题提炼逻辑图；表1 研究脉络时间轴（time 模式） |

字数算法：`总字数 = 开篇导语(150–200) + 阶段数 × 850 + 收口段(200)`。

---

## 2. 结构骨架（照抄这一层，只换内容）

```
1.3 国内外研究现状
    ├─ 导语段（150–200 字）：调研边界 + 声明按时间阶段展开 + 一句话点出推进主线
    ├─ 图1 文献调研总体逻辑图
    ├─ 表1 研究脉络时间轴（阶段/年份/篇数/代表工作/标志性进展/遗留问题）
    ├─ （1）<阶段一：YYYY–YYYY 年>：<该阶段解决了什么（写成判断句）>
    │      ├─ 段A：按年份由早到晚铺陈——谁在先、谁改进了什么、指标从多少到多少
    │      └─ 段B：阶段收口——当时卡在哪、为什么转向下一阶段
    ├─ （2）<阶段二：YYYY–YYYY 年>
    └─ （3）<阶段三：YYYY 年至今>

1.4 发展动态分析及问题分析
    ├─ （1）发展趋势1：<判断句，一句话给结论>
    ├─ （2）发展趋势2：<判断句>
    ├─ （3）发展趋势3：<判断句>
    ├─ 图2 核心问题提炼逻辑图
    └─ 收口段：把三条趋势压成 2 个待解决的关键问题，用「一是…二是…」展开
```

**默认按时间阶段展开**（`organize_by: "time"`）。理由是评审看研究现状，真正想知道的是
「这个方向走到哪一步了、下一步往哪走」，而不是「有哪些人做过」。三个阶段最稳：
问题提出与原理验证 → 方法体系形成 → 精细化与工程化。

什么时候改用主题式（`organize_by: "topic"`）：方向内部是**多条并列技术路线**而非迭代关系
（例如「实验测量 / 数值模拟 / 理论分析」三块各自独立演进），按时间切会切断每条线的完整性。
改法只动 `report_config.json` 一个字段，骨架会重新按主题分节（节内仍按年份推进）。

**不要**添加"研究综述""文献计量""研究热点"这类标题；基金本子不认这种写法。

## 3. 段内写法（决定成败的一层）

每个研究阶段（或主题小节）固定两段，两段的任务不同：

### 段A —— 铺事实，按年份由早到晚建立"这个方向已经做到哪"

句式骨架（按需混用，不要每句都同一个模子）：

- `Xxx等[12]（2016）提出<方法>，将<指标>由 A 提升至 B。`
- `国内外多名学者[7][8][9]通过实验先后发现<现象>。`
- `针对<问题>，学者在 2016–2018 年间发展了<方法A>[33]、<方法B>[34]以及<方法C>[35]。`
- `<因素>如<A>[17]、<B>[18]、<C>[19]等都会对<对象>产生重大影响。`

要点：
1. **按时间推进，但不是逐年流水账。** 年份是坐标，不是结构——正确的是
   「2013 年 A 证明了可行性 → 2016 年 B 把指标翻了一倍 → 2019 年 C 才发现瓶颈在 X」，
   错的是「2013 年 A 做了…，2014 年 D 做了…，2015 年 E 做了…」逐个报菜名。
   判断标准：删掉年份后这段还成立，说明写成了主题式；把年份按乱序读一遍就荒唐，说明时间顺序是对的。
2. **每条结论尽量带数字和单位**：`传播波速为 1439.97 m/s`、`计算效率提高 1 个数量级（942 分钟→90 分钟）`、`效率提高 3.77 至 5.91 倍`、`误差保持在 1% 以下`。没有数字就写清"定性结论 + 适用条件"。
3. **多篇同向结论并置**时用连续编号 `[7][8][9]`，**不用** `[7-9]`（样张全文均为逐个列出）。
4. 同一阶段内若有多条并行路线，**先按路线分组，组内再按年份**，不要为了时间顺序把同一路线拆散。

### 段B —— 做判定，收口到"没解决什么"

固定收口句式（择一，必须出现判断词）：

- `虽然国内外学者针对<对象>研究已取得丰硕成果，但在<具体环节>时仍然有巨大挑战。`
- `虽然上述方法可以<做到X>，但是对<Y>的估计过于保守，在<Z>方面仍有很大提升空间。`
- `但针对<对象>缺少不同<方法/路线>之间精细的对比和分析。`
- `这一时期虽已能<做到X>，但受限于<条件>，尚无法<Y>，从而催生了<下一阶段的做法>。` ← 时间式首选
- `这类新方法在推广至<更复杂场景>中仍有巨大挑战。`

要求：**收口句必须指向一个可被本项目攻克的缺口**，不能是"有待进一步研究"这种空话。
按时间式写作时，每个阶段的段B 还要承担"承上启下"的职责——它得解释清楚为什么会走到下一阶段。

## 4. 「发展动态分析」的写法

三条趋势，每条 250–400 字，标题是**判断句而非名词短语**：

- ✅ `（1）发展趋势1：爆轰发动机数值模拟已成为推动技术工程应用的关键驱动力`
- ✅ `（3）发展趋势3：人工智能赋能数值方法有望大幅度提高计算效率和稳定性`
- ❌ `（1）数值模拟的发展`

每条内部三段式：`历史脉络/现状事实 → 现存局限（点名具体软件或方法）→ 由此导出的必然方向`。
第三条趋势要**自然导向本项目要做的事**，为下一节的"拟解决的关键问题"铺路。

图2 之后必须落成关键问题清单：

```
因此，本项目拟发展<一句话定位>，以解决以下两大难题：
一是如何<问题1>？<2–3 句展开，含技术难点与理论依据>
二是如何<问题2>？<2–3 句展开>
```

## 5. 引文规则

1. 按**正文出现顺序**编号 `[1]`、`[2]`…，全文连续不跳号。
2. 位置：跟在被引结论/对象后，标点之前 —— `…起爆困难的现象进行了深入剖析[10]。`
3. 中文文献首次出现用 `王放等人[13]`，英文用 `Sheng等[10]`（姓 + 等，不加名，不加年份）。
4. 参考文献表按 GB/T 7714 顺序编码制：

```
[1] 作者A, 作者B, 作者C. 题名[J]. 刊名, 年, 卷(期): 起页-止页.
[2] 苟小龙, 孙文廷, 陈正. 燃烧数值模拟中的复杂化学反应机理处理方法[J]. 中国科学: 物理学、力学、天文学, 2017, 47(7): 56-72.
```

文献类型标识：`[J]` 期刊、`[C]` 会议论文集、`[D]` 学位论文、`[R]` 报告、`[M]` 专著、`[P]` 专利、`[EB/OL]` 网络资源。
英文作者 3 人以上用 `et al.`，中文 3 人以上用 `等`。

## 6. 语言与禁忌

**必须有**：第三人称客观陈述；判断句；量化数值；中英术语并列（首次出现 `旋转爆轰发动机（rotating detonation engine, RDE）`，之后只用中文或只用缩写）；专业名词保留英文原词。

**禁止出现**：
- 「本文」「我们认为」「笔者」——调研报告是替申请人陈述领域现状，不是自述
- 「众所周知」「不言而喻」——空话
- 「综述」「文献计量」「研究热度」——基金本子语境不认
- 整段英文摘要式复制——必须转述
- 「诚实说明」「受限于时间/数据」「以上仅供参考」——不写免责声明；做不到就写「待核实」
- 未经核实的 IF / 分区数字——查不到就留空，**绝不编**

## 7. 交付物两档

| 交付物 | 内容 | 用途 |
|---|---|---|
| `研究现状_<主题>.md` / `.docx` | 完整版：1.3 全节 + 1.4 全节 + 参考文献表 | 直接贴进申请书 |
| `研究现状_<主题>_速览.md` | 一页纸：5 条核心判断 + 方法对比表 + 3 个空白点 | 组内汇报 / 自检 |
| `未获取资料清单.md` | 未拿到全文的条目：DOI、可点链接、出版方、失败原因、获取通道 | 交给用户去补全文，随报告一起交付 |

报告里引用的文献如果还没拿到全文，只能凭摘要写一句「据摘要」，不得展开成方法细节；
这类条目要在清单里能对上号。

完整版每一条判断都要能在 `04_精读笔记/` 里找到出处（`[p.N]` 页码 + 短引用），
写不出出处就降级为「推测」并标注，不允许凭印象写。

页码以 `03_解析全文/md/<ID>.md` 的 `## 第 N 页` 为准。若该篇 `extract_method` 是 `OCR` 或 `多模态`，
说明文字是机器从图像转写的——**凡是引用进报告的数值，都要回 `03_解析全文/pages/<ID>/` 的页面图核对一遍**，
转写错一个数字比少一条引文严重得多。

## 8. 用户可改项（交互时只动这里）

| 参数 | 默认 | 用户可改成 |
|---|---|---|
| 组织方式 `organize_by` | `time`（按研究阶段由早到晚） | `topic`（按技术主题分节，节内仍按年份推进） |
| 目标字数 | 3500 / 1750 | 任意，脚本按比例缩放段落数 |
| 阶段/小节数 `sections` | 3（time）/ 4（topic） | 2–6；time 模式下按年跨度等分，不会超过实际年份跨度 |
| 时间轴表 `include_timeline` | true | false（不要「研究脉络时间轴」表） |
| 中文文献占比 | 25% | 0–60% |
| 参考文献起始编号 | [1] | 若并入已有正文，改为接续编号 |
| 引文风格 | 顺序编码制 GB/T 7714 | 著者-出版年制（需同时改正文标注） |
| 是否要图 | 2 张逻辑图（按需生成） | 不要图 / 加方法对比表 |

改动落在 `05_报告/report_config.json`，`make_report.py` 每次重跑都读它，保证反复交互不漂移。

**注意**：`--check` 只在 `organize_by=time` 时检查「时间顺序」一项（统计正文年份的倒退比例，>50% 判失败）。
改成 topic 模式后这项自动跳过，因为主题式本来就会在不同小节间来回跳年份。
